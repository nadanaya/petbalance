# 발표·검증 가이드

## 30초 설명

우애영은 보호자가 저장한 반려동물 프로필에 사료·영양제의 하루 급여량을 넣으면, 여섯 성분의 총량을 기준 범위와 비교하고 추가 후보의 안전성을 다시 계산하는 웹 데모다. 제품 데이터가 불완전할 때는 실제값처럼 보이게 합산하지 않고 추정이라고 밝힌다.

## 자료구조와 역할

| 구조 | 위치 | 이유 |
| --- | --- | --- |
| 직접 구현한 제품 ID 해시 테이블 | `src/localEngine.ts`, `backend/app/catalog_index.py` | 급여 목록의 ID·바코드로 제품 성분을 평균 O(1)에 찾는다. |
| 고정 길이 성분 누적 배열 | 두 계산 엔진의 `nutrientIds`·`NUTRIENT_IDS` | 여섯 성분을 같은 인덱스로 사료·영양제에 나눠 누적한다. |
| 제품명 Trie | `src/localEngine.ts`, `backend/app/catalog_index.py` | 제품명·브랜드의 접두어를 문자 단위로 찾아 자동완성한다. |
| 최대 힙과 탐욕 재평가 | `localRecommend`, backend `recommend` | 가장 높은 점수 후보를 꺼내고 총량·Ca:P 비율을 다시 검사한 뒤 다음 후보를 평가한다. |

> backend의 Trie와 카탈로그 인덱스는 로컬 FastAPI 모드에서 사용한다. 공개 Pages는 브라우저 데모 엔진으로 동작하므로, 발표에서는 두 모드의 역할을 구분해서 설명한다.

## 데이터 판단 규칙

1. 반려동물 식품 카테고리가 확인된 Open Pet Food Facts 제품만 검색 결과로 허용한다.
2. 추적하는 6종 성분이 전부 확인된 사료만 실제값 합산을 허용한다.
3. 불완전 성분표는 일부 값을 0으로 채우지 않는다. 완전사료 선택 시 최소 권장량으로 추정하고 경고한다.
4. 수동 입력은 라벨의 1회 제공량을 기준으로 단위를 먼저 맞춘 뒤 하루 급여 비율을 한 번만 적용한다.

## 데모 순서

1. 분석 화면에서 이름·종·체중·나이와 성장기 개의 예상 성체 체중(kg)을 입력해 프로필을 저장한다.
2. 반려동물 기록에서 저장된 프로필을 확인하고 `이 프로필로 분석`을 누른다.
3. 제품을 검색해 추가하거나, 검색되지 않는 제품은 라벨 성분을 직접 입력한다.
4. 분석 결과에서 추정 표시와 경고를 확인하고 추천 후보를 추가해 재분석한다.
5. 결과를 기록으로 저장한 뒤 개별 삭제와 전체 삭제 상태를 보여 준다.

## 한계와 다음 우선순위

- 영양 기준은 FEDIAF Nutritional Guidelines 2025의 생애주기별 1000 kcal ME 표를 적용한다. 비타민 E와 오메가3는 현재 제품 단위·정의가 달라 기준 없음으로 분리한다.
- 원문 표·단위 변환·각주 대조 내용은 [backend 검증 기록](https://github.com/WooAeyoung/backend/blob/main/docs/standards-validation.md)에서 확인할 수 있다.
- 브라우저 엔진과 FastAPI 엔진은 같은 검산 시나리오로 비교하는 회귀 테스트가 필요하다.
- OCR·가격 비교·의학적 처방은 제외 범위다.
